# AIOps Agent 智能运维诊断与监控服务：需求规格说明书

> 状态：草稿，待评审  
> 版本：v0.1  
> 日期：2026-09-07  
> 项目代号：aiops-agent / 项目 A

## 1. 背景与目标

企业内部通常存在多台服务器、多个应用服务和大量运维日志。当系统出现“CPU 高、磁盘满、接口报错、服务不可用”等问题时，运维和研发人员需要登录多台主机、手工执行命令、翻阅日志和排障文档才能定位原因，效率低且依赖个人经验。

本项目建设一个面向运维场景的 Agent 服务：

- 用户用自然语言描述问题；
- Agent 自动调用系统状态、日志查询、进程/端口检查和排障手册检索等工具；
- Agent 依据工具结果生成带来源和处置建议的回答；
- 服务提供完整 API、监控指标、结构化日志和容器化交付能力。

项目同时承担两个目标：

1. 成为可写入简历的端到端 AI Agent 应用后端项目；
2. 验证“Python + FastAPI + Agent + RAG + 可观测性 + CI/CD”的企业级开发闭环。

## 2. 项目范围

### 2.1 本期建设范围

- 提供会话管理与多轮对话 API；
- 提供可扩展的 Agent 工具调用能力；
- 提供系统状态、进程/端口检查、日志查询类诊断工具；
- 提供排障手册文档上传、RAG 检索与来源引用；
- 提供鉴权、限流、结构化日志与 Prometheus 指标；
- 提供自动化测试、Docker 部署与 GitHub Actions CI；
- 支持无外部模型 Key 的 Mock 模式，保证离线可开发、可测试。

### 2.2 不在本期范围

- 不做多机房、多集群级分布式监控平台；
- 不直接开放任意 shell 命令执行，所有诊断能力必须经过受控工具封装；
- 不做复杂工单系统、CMDB 或告警通知平台；
- 不做商用级向量数据库和用户中心，采用适合 MVP 的轻量方案并预留替换接口；
- 不做 Vue 管理后台，仅提供 API 与文档，后台后续作为可选增强。

## 3. 用户与业务场景

| 角色 | 典型诉求 | 期望价值 |
|---|---|---|
| 运维工程师 | 快速确认服务器负载、内存、磁盘和进程状态 | 减少重复登录和手工执行命令 |
| 研发/值班人员 | 定位“最近接口报错”的日志线索和原因 | 缩短初步排查时间 |
| 排障新手 | 查询“磁盘满/OOM/502 应该怎么办” | 基于排障手册获得可执行处置步骤 |
| 服务管理者 | 查看 Agent 服务健康、调用量与延迟 | 服务可观测、可审计 |

## 4. 核心业务需求

优先级定义：

- P0：本期必须完成，否则项目不能交付；
- P1：核心价值功能，本期完成；
- P2：质量与交付必备项；
- P3：可选增强，不影响主线交付。

### 4.1 会话与对话

| 编号 | 优先级 | 需求 | 验收标准 |
|---|---|---|---|
| REQ-101 | P1 | 系统支持创建会话、延续会话、保存多轮消息 | 用户不带会话 ID 时自动创建；带会话 ID 时能读取历史 |
| REQ-102 | P1 | Agent 根据用户消息自动判断是否调用工具，最多执行 N 次工具后输出最终回答 | 超限时明确返回已执行步骤且不进入死循环 |
| REQ-103 | P0 | 支持 Mock 模型离线完成全部流程 | 无外部 API Key 时可完成普通对话与工具调用 |
| REQ-104 | P1 | 支持 OpenAI 兼容模型接口切换 | 配置供应商地址、Key、模型名后可完成真实调用 |
| REQ-105 | P2 | 多轮消息仅保留有效上下文 | 历史记录截断策略可配置，不会无限增长 |

### 4.2 诊断工具

| 编号 | 优先级 | 需求 | 验收标准 |
|---|---|---|---|
| REQ-201 | P0 | 提供“系统状态”工具：CPU、内存、磁盘、主机、进程概览 | 通过自然语言“查看服务器状态”可触发并返回可读结果 |
| REQ-202 | P1 | 提供“进程/端口/服务健康”检查工具 | 可检查指定进程、监听端口与服务健康 |
| REQ-203 | P1 | 提供“日志检索与错误归类”工具 | 可按时间、关键字检索日志，返回截断后的结构化片段 |
| REQ-204 | P1 | 所有工具输出限制大小，防止污染上下文 | 输出超过阈值时截断并提示 |
| REQ-205 | P0 | 工具只能通过注册表执行，不允许任意命令注入 | 工具 schema 校验参数，未注册动作不可执行 |

### 4.3 排障手册 RAG

| 编号 | 优先级 | 需求 | 验收标准 |
|---|---|---|---|
| REQ-301 | P0 | 支持上传 Markdown/TXT 排障手册 | 上传成功后返回文档 ID 与分块数量 |
| REQ-302 | P0 | 文档切分、本地向量化并入库 | 可检索出与问题相关的内容片段 |
| REQ-303 | P1 | Agent 回答运维处置问题时引用知识库片段 | 回答中携带来源文档/片段名称 |
| REQ-304 | P1 | 支持文档列表与删除 | 删除后相关片段不可再被检索 |
| REQ-305 | P2 | 知识库检索失败或为空时明确降级 | 回答告知未找到资料，不编造内容 |

### 4.4 服务、可观测性与安全

| 编号 | 优先级 | 需求 | 验收标准 |
|---|---|---|---|
| REQ-401 | P0 | 提供健康检查接口 `/healthz` | 服务可启动且返回 `200` |
| REQ-402 | P0 | 提供 Prometheus 指标 `/metrics` | 包含请求量、延迟、工具调用等基础指标 |
| REQ-403 | P1 | 输出结构化日志 | 关键请求、Agent 步骤、工具调用可被日志检索 |
| REQ-404 | P0 | API 使用 API Key 鉴权 | 无 Key 或错误 Key 返回 401 |
| REQ-405 | P2 | 提供基础限流 | 超限返回 429 且不影响服务稳定性 |
| REQ-406 | P2 | 关键接口提供自动化测试 | `pytest` 全量通过 |

### 4.5 工程交付

| 编号 | 优先级 | 需求 | 验收标准 |
|---|---|---|---|
| REQ-501 | P1 | 提供 Dockerfile 与 Docker Compose | 容器内可一键启动服务 |
| REQ-502 | P1 | 提供 GitHub Actions CI | Push/PR 自动运行测试 |
| REQ-503 | P1 | README 包含快速启动、API 示例与环境变量说明 | 新开发者可独立运行项目 |

## 5. 可选增强需求（P3）

- OPS-602：定时巡检与简易告警；
- OPS-603：Agent 工具调用审计页面或管理 API；

- OPS-605：接入真实向量库或 Postgres/MySQL 替换 SQLite。

## 6. 非功能需求

| 分类 | 要求 |
|---|---|
| 性能 | Mock 模式下普通对话接口目标响应时间小于 2 秒；单次工具调用默认超时 5 秒 |
| 可用性 | 服务进程崩溃后可快速重启，数据文件可持久化；提供健康检查 |
| 安全 | 禁止未注册 shell 动作；日志输出截断；敏感配置通过环境变量注入，不写入代码库 |
| 可观测性 | 请求级指标、结构化日志、工具执行记录三者齐备 |
| 可维护性 | 模块按配置/存储/Agent/RAG/API/工具/可观测性分层；核心模型使用 Pydantic 定义 |
| 可移植性 | 开发环境支持 Windows/macOS/Linux；容器与 CI 以 Linux 为目标 |
| 测试性 | Mock 模型保证无外部依赖测试；核心流程均有自动化测试 |
| 数据 | MVP 使用 SQLite；存储层提供抽象，便于后续替换 |

## 7. 数据需求（MVP 数据范围）

会话、消息、文档、文档分块、向量数据、工具调用审计。其中向量数据 MVP 阶段随分块持久化保存，不依赖外部向量数据库。

## 8. 对外接口范围

MVP 需要暴露：

- 健康检查与指标接口；
- 会话创建、会话消息查询；
- 对话请求接口；
- 文档上传、列表、删除；
- 知识库检索接口（用于验证 RAG）；
- 工具列表接口；
- 系统状态接口。

## 9. 测试与验收策略

### 9.1 测试层级

1. 单元测试：工具参数解析、文档分块、向量检索、历史截断；
2. 接口测试：会话、对话、鉴权、限流、文档 API；
3. 集成测试：Mock 模型下的完整 Agent 工具调用与 RAG 流程；
4. 构建验证：Docker 镜像构建与 CI 测试。

### 9.2 发布验收标准

- 所有 P0/P1/P2 需求有对应验收；
- `pytest` 全量通过；
- Mock 模式下核心用户场景可演示；
- README 与设计文档齐全；
- 代码已提交到 GitHub `main` 分支。

## 11. 风险与依赖

| 风险 | 影响 | 应对 |
|---|---|---|
| Linux/Docker 基础不足 | 部署和排障卡顿 | 本地 Windows 优先可运行，Docker 后验证；提供最小命令练习 |
| Agent 工具循环失控 | 死循环或上下文膨胀 | 限制最大轮数、输出截断、超时控制 |
| RAG 检索效果差 | 回答无依据 | MVP 内置本地向量实现，后续可替换；回答必须引用来源 |
| 真实模型 API 不可用 | 演示受限 | Mock 模式保证全流程，真实接口做成配置项 |
| 3 周周期被其他学习挤占 | 交付延期 | 严格按里程碑切割，P3 全部后置 |

## 12. 待评审与待确认问题

1. 是否确认本期只做单机/本机诊断，不做远程多主机 Agent；
2. 是否确认 MVP 使用 SQLite，后续再替换 PostgreSQL/MySQL；
3. 是否确认排障手册 RAG 的本地向量方案满足当前交付；
4. 是否将 GPU/算力工具作为 P3 后置；
5. 是否接受“任意 shell 执行”不在本期范围内。
